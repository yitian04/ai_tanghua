# 轨迹执行模拟

素材库标准轨迹详情、文字轨迹结果和轨迹规划的“执行模拟”使用同一个二维播放器。
素材缩略图保持静态；合成工程预览、URP/G-code 内容摘要及轨迹排版编辑器保持原用途。

蓝色工具头点表示出料，橙色表示收料，白色描边帮助定位；状态文字同时显示 Z 高度。
浅灰线是完整参考路径，深蓝线是已完成的绘制；灰色虚线表示空走，可以关闭。
画布等比适配所有运动点，X 向右、Y 向下，播放期间不移动视角。

首次打开暂停，默认 1 倍速，可选 0.25、0.5、1、2、4、8 倍。
上一笔、下一笔及指定笔号跳转到目标笔的绘制起点，保留原来的播放/暂停状态。
重新开始回到首点并清除已完成路径，同样保留播放状态和倍速。
播放结束暂停，再按播放从头开始；进度条只读。
普通页面重绘保留游标；更换轨迹、重新进入素材详情从初始暂停开始。
隐藏页面或收起预览会暂停，关闭或卸载后释放动画与监听器。

## 文件语义

播放器只读取已解析的 `Trajectory`，不读取本地路径、不执行设备命令。
按点数组顺序运行，不按 point_id 排序，也不改变原始文件。
每段 A→B 使用目标点 B 的 drawing 命令与 speed_mm_s；名义时间是三维距离除以该速度。
首次位置取文件首点，不假设此前的机器人位置，不包含加速度、准备位、融合和阀门延时。
因此它是轨迹执行示意，不是机械臂实物耗时预测。

连续出料且 curve_id 相同的点划为一笔，按执行顺序重新编号。
收料或者 curve_id 变化分笔，允许重复编号、不连续编号及单点笔画。
编号变化但没有收料时，模拟器如实显示出料连接并提示，不插入抬笔。
重合点的零时长状态切换仍按原顺序处理；全部重合可瞬时完成。
游标同时记录索引与段内进度，避免相同时间戳的笔画无法定位。

## 软件检查

- `python -m unittest discover -s tests`
- `node --test tests/trajectory_player.test.mjs`
- `python tests/browser_trajectory_player_check.py http://127.0.0.1:8525`：三个应用入口及实际操作。
- 单独启动 `streamlit run tests/fixtures/trajectory_player_app.py --server.port 8526`，
  再运行 `python tests/browser_playback_runtime_check.py http://127.0.0.1:8526`：
  页面重绘、隐藏/卸载、切换文件、零时长笔画以及真实样本和一万点压力样本。

浏览器检查需要 Playwright 和 Chrome，结果存于 `.artifacts/software_checks`。
性能按播放器实际动画更新次数计数，目标为桌面至少 30 fps，渲染上限约 60 fps。
2026-11-03 浏览器实测：3,317 点真实轨迹约 60 fps，10,000 点、1,000 笔样本约 59 fps。
数值随设备和浏览器负载变化，具体记录见 `trajectory_player_performance.json`。
以上检查不连接或执行真实机械臂。
